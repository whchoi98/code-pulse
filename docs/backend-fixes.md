## 추가 수정: 윤문 작업 간 동시 저장

같은 날 후속 작업으로 `tools/polish-content.ts`의 편집 작업 간 충돌도 수정했다. 기존의 항목 병합을 `tools/editorial-merge.ts`로 분리하고, 원문 해시가 같으며 저장된 값보다 `explanationEditedAt`이 더 새로운 편집만 적용하도록 했다. 저장 재시도마다 다시 읽은 항목과 비교하므로, 다른 작업이 먼저 저장한 최신 윤문을 오래된 작업 결과로 되돌리지 않는다. 편집 시각이 같거나 없는 작업 결과도 저장된 해설보다 우선하지 않는다.

병합은 윤문 도구가 생성하는 `explanation`, `editorialVersion`, `explanationEditedAt`만 적용한다. 최신 스냅샷의 원문, 출처, 발표일, 확인 시각, 참조 링크와 원문 해설 생성 모델 정보는 유지한다. 원문 해시가 달라진 항목에는 이전 원문을 바탕으로 만든 윤문을 적용하지 않는다.

## 추가 기능: 선택적 해설 모델 갱신

`CollectOptions.refreshModel?: boolean`과 수집 CLI의 `--refresh-model`을 추가했다. 기본값은 `false`다. 명시적으로 활성화하고 목표 `modelId`를 지정하면, 저장된 `explanationModel`이 다른 항목만 새 모델로 해설을 생성한다. 기존 모델 기록이 없는 항목도 대상에 포함하며, 이미 목표 모델인 항목은 다시 생성하지 않는다.

현재 피드나 조회 기간에서 빠진 항목도 저장된 검증 원문으로 갱신한다. RSS만 관찰한 GitHub 대표 릴리스에는 기존 대표 원문과 확인 시각을 사용한다. 같은 원문을 새 모델로 해설하는 동안에는 기존 `ready` 해설을 유지하고, 생성이 성공한 후에만 해설과 모델·편집 메타데이터를 교체한다. 생성 실패와 예산·시간 제한도 기존 해설을 숨기지 않는다. 실제 원문 해시가 달라졌을 때 이전 해설을 무효화하는 기존 규칙은 유지한다.

기존 생성 예산, 14분 제한, 체크포인트를 함께 사용한다. 완료 시에는 ETag 재시도 후 병합된 스냅샷까지 확인하며, 목표 모델로 바뀌지 않은 항목이 남으면 `partial`로 기록한다. 더 늦게 저장된 윤문이 갱신 결과보다 우선한 경우도 여기에 포함한다. 전체 출처 수집 실패의 `failed` 판정은 기존과 같다. 같은 옵션으로 다시 실행하면 아직 목표 모델로 바뀌지 않은 항목만 이어서 갱신할 수 있다.

```bash

```

## 추가 기능: 시작일 지정과 병렬 해설 생성

`CollectOptions.sinceDate?: string`을 추가했다. `YYYY-MM-DD` 형식과 실제 달력 날짜를 검사하고 미래의 시작일을 거부한다. 지정된 날짜의 UTC 00:00과 현재 시각을 모두 포함한다. 엔진을 직접 호출할 때 시작일을 생략하면 기존의 기본 45일 조회 범위를 유지한다. 자료 조회 도우미에서 재사용할 수 있도록 `earliestPublishedAt`을 UTC epoch milliseconds로 계산하며, 이번 작업에서는 기존 자료 조회·파싱 블록을 수정하지 않았다.

CLI 기본 조회 범위는 `--since 2026-01-01`이다. `--days`를 명시한 실행만 종전의 rolling 기간을 사용한다. `--days`와 `--since`를 함께 명시하면 오류로 종료하며, 시작 로그에는 실제 선택한 `sinceDate` 또는 `days`를 기록한다.

해설 생성은 기존 제품별 교차 순서에 따라 최대 3개를 함께 실행한다. 생성 횟수는 호출 전에 공통 예산에서 차감하고, 14분이 지나면 추가 생성을 시작하지 않는다. 진행 중인 배치는 완료한 뒤 저장한다. 이전 체크포인트 이후 최소 5개 항목이 처리됐으면 배치 경계에서 저장하므로, 3개씩 처리하는 구간에서는 보통 6개마다 체크포인트가 생긴다. 모든 쓰기는 직렬로 실행한다. 한 요청의 실패가 다른 해설 생성을 중단하지 않으며, 기존 모델 갱신과 최신 윤문 보존 규칙도 유지한다.

- CLI 기본 시작일, 명시적 rolling 기간, 두 옵션의 충돌과 시작 로그

## 추가 기능: Codex 전체 조회 완료 범위

`SourceStatus.historySince?: string`을 추가했다. 이 값은 해당 범위에서 읽은 대상 항목이 최종 스냅샷에 모두 저장됐음을 나타내는 UTC ISO 시각이다. 해설이 `pending`이어도 원문 항목이 모두 저장됐으면 완료 범위를 확정할 수 있다. 새 범위는 최종 저장에만 반영한다. 중간 체크포인트에서는 기존에 확정된 범위만 유지하므로, 최종 저장 전에 중단된 실행이 저장하지 못한 과거 기록을 완료한 것으로 표시하지 않는다.

Codex GitHub 출처의 기존 `historySince`가 요청 하한보다 이르거나 같을 때만 실제 reader의 하한을 `max(요청 하한, 현재 시각 - 45일)`로 올린다. 요청 범위를 완료했다는 기록이 없으면 최초 실행, 전체 읽기 실패 후 재실행, 중간 체크포인트만 남은 실행 모두 요청한 전체 경계까지 읽는다. 기존 완료 범위보다 넓은 기간을 요청한 경우도 같다. 다른 출처의 읽기 범위와 최종 항목 필터에는 요청 하한을 그대로 사용한다. 이미 저장된 과거 항목과 그 해설 재시도·모델 갱신도 유지한다.

완료 범위는 출처의 최근 확인 시각과 별도로 병합한다. 출처 오류나 더 짧은 재확인이 기존 범위를 줄이지 않으며, ETag 재시도에서는 더 이른 완료 범위만 보존하거나 확장한다. 더 늦은 출처 상태가 저장됐더라도, 먼저 시작한 전체 조회가 더 넓은 기간의 저장을 완료했다면 그 범위를 반영한다.

엔진·공유 타입·전용 테스트의 strict 타입 검사도 통과했다. 전용 테스트는 `readSourceHistory` 경계를 대체하여 조회 하한과 저장·병합 동작을 검증한다. 원격 자료 조회, 모델·AWS 호출, 운영 데이터 변경은 수행하지 않았다. 실제 페이지 reader와의 통합 검증은 별도 작업에서 수행한다.
