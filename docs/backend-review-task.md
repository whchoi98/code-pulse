# 수집기와 API 독립 검토

작업 경로: /home/ec2-user/my-project/code-assistant-changelog

docs/superpowers/specs/2026-10-07-code-pulse-design.md와 계획의 Task 1을 기준으로 검토한다. 현재 프로젝트는 유효한 Git 저장소가 없으므로 Git 명령 대신 파일을 읽는다.

범위는 src/collector/**, src/server/**, src/shared/types.ts, tools/polish-content.ts, tools/apply-editorial.ts와 해당 tests/*.test.ts다. 프런트엔드와 인프라는 별도 검토 중이므로 구체적인 계약 문제를 확인할 때만 읽는다.

공식 자료는 Claude Code와 Codex GitHub Releases, Codex 공식 RSS, Kiro 공식 changelog다. 전체 원문은 S3 비공개 영역에 남기며 API는 짧은 인용과 공식 링크만 제공한다. 발표일과 확인 시각을 구분하고, 시험판과 미래 발표를 걸러낸다. 같은 Codex CLI 버전의 RSS와 GitHub 글은 합친다.

부분 출처 실패 시 기존 글과 다른 제품의 수집을 유지한다. 해설 생성에 실패한 글은 원문을 보존하고 다음 실행에서 재시도한다. 개별 근거 인용은 원문에 있어야 하며 합계 25단어를 넘지 않는다. 한국어 해설의 엠대시와 가운뎃점, 과장된 표현을 걸러내고 별도 윤문 단계를 거친다.

파일과 S3 저장은 조건부 쓰기로 동시 갱신을 처리한다. 수집 결과는 5개마다 저장한다. 이때 아직 끝나지 않은 실행을 완료 기록으로 남기지 않는다. 전체 실행이 끝나면 run을 기록한다. 캐시는 읽기 실패 시 이전 자료를 제공하되 stale을 표시한다.

실제 첫 수집에서 77개를 수집한 뒤 중복 2개를 합쳐 75개를 보관했다. 근거 검증을 통과하지 못한 두 항목은 전체 공식 원문과 대조해 docs/initial-editorial.json으로 보완했다. 현재는 기존 자료의 윤문을 진행한다. 이미 실행한 수집기가 최신 코드를 모두 사용한 것은 아니므로 최종 AWS 수집은 최신 이미지로 별도 검증한다.

이미 검증한 범위: 파서, 중복과 수정, 부분/전체 실패, pending 재시도, 저장 충돌, 한국어와 근거 검증, 공개 원문 차단, 캐시 장애, 정적 파일 응답. 테스트는 Vitest 3에서 통과했고 보안 갱신 후 Vitest 4와 Node 22로 재검증 중이다. 반복적인 전체 테스트 실행은 하지 않는다. 구체적인 의심이 있으면 작은 재현만 실행한다.

구현을 수정하지 말고 docs/backend-review.md에 명확한 파일/줄과 근거, 심각도를 기록한다. 일반론과 낮은 확률의 가정보다 실제로 잘못될 수 있는 동작을 우선한다. 검토용 보고서 외에는 파일을 바꾸지 않는다. 하위 에이전트를 만들지 않는다.
