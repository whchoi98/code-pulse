# Code Pulse 화면 구현 보고

검증일: 2026-10-07

Task 2의 React 화면과 브라우저 테스트를 구현했다. 사이트 이름은 Code Pulse이며 페이지 이동과 정적 파일 경로는 상대 경로를 사용한다.

독립 검토에서 확인한 네 가지 문제와 해설 준비 상태 표시를 수정했다. 공식 로고, 방문 집계와 서비스 변경 기록을 반영한 현재 화면은 Node 22.23.3에서 Chromium 테스트 43개와 프런트엔드 범위의 엄격한 타입 검사를 통과했다. 세부 결과는 마지막 절에 기록했다.

## 화면 방향

공식 변경 기록을 읽고 적용할 내용을 고르는 개발자를 위한 화면이다. 첫 화면에서 제품, 발표일과 변경 내용을 빠르게 연결할 수 있도록 구성했다.

| 역할 | 값 |
| --- | --- |
| 바탕 | `#f4f7fb` |
| 읽기 영역 | `#ffffff` |
| 본문 | `#17283f` |
| 보조 문구 | `#617086` |
| 강조 | `#087f8c` |
| 경계선 | `#dce4ed` |

제목과 제품 이름에는 Space Grotesk와 Noto Sans KR을 사용한다. 한국어 본문은 Noto Sans KR, 날짜와 버전은 IBM Plex Mono를 쓴다.

대표 요소는 제품 세 행과 최근 날짜 일곱 열로 구성한 활동표다. 칸마다 실제 발표 건수를 표시하며 선택하면 제품과 날짜 필터를 함께 적용한다. 큰 통계 영역 대신 날짜와 글의 관계를 탐색하는 데 화면을 사용한다.

```text
로고             변경 기록 / 저장한 글       출처 / 테마
제목과 확인 상태                   최근 7일 제품 활동표
제품 필터
검색                                     종류 / 날짜
날짜별 글 목록                           출처 안내
```

모바일에서는 제목, 활동표, 필터와 글 목록 순서로 배치한다. 자체 검토 후 목록 요약과 상세 본문의 글자 크기를 키우고 보조 문구의 명도를 낮췄다. 날짜, 제품 표식과 줄 간격으로 읽기 순서를 구분한다.

## 구현한 기능

- `/api/feed`에서 목록을 읽고 `/?entry=<id>`를 열 때 `/api/entries/:id`에서 상세를 읽는다.
- 제품, 검색어, 종류, 시작일, 종료일과 저장한 글 상태를 URL 쿼리에 반영한다.
- 발표일 내림차순으로 정렬하고, 목록에서 20개씩 더 볼 수 있다.
- 더 보기로 펼친 목록, 검색 조건, 스크롤 위치와 키보드 초점을 상세 화면에서 돌아왔을 때 복원한다.
- localStorage에 글 ID와 테마를 저장한다. 브라우저 저장에 실패하면 현재 창의 저장 목록을 유지하고 제한을 알린다.
- 공유할 때 검색어와 저장 필터를 제외한 상세 주소를 복사한다. 클립보드를 사용할 수 없으면 복사할 주소를 보여준다.
- 한국어 설명, 의미, 적용 전 확인할 내용, 짧은 원문 근거와 공식 링크를 표시한다. 생성 설명에는 AI 해설 표식을 붙인다.
- API 실패, 로딩, 검색 결과 없음, 정상 확인 후 빈 목록, 해설 준비 중, 일부 출처 실패와 오래된 자료를 구별한다.
- 공식 출처별 최근 확인 시각, 마지막 성공 시각과 최근 발표일을 dialog에 표시한다.
- dialog 초점 순환과 Escape 닫기, 본문 바로가기, 검색 단축키 `/`, 명확한 초점 표시와 reduced-motion을 적용했다.
- 라이트 모드와 다크 모드에서 390px 화면의 가로 넘침을 검사했다.

## 날짜 기준

목록, 날짜 필터와 활동표는 API의 `publishedDate`를 사용한다. 출처 확인 시각으로 글의 발표일을 바꾸지 않는다.

`datePrecision: day`인 상세는 날짜만 표시한다. 시각이 있는 상세는 원문 발표일과 한국 시간으로 환산한 전체 날짜와 시각을 함께 보여준다. UTC 오후 발표가 한국 시간으로 다음 날이 되는 경우도 날짜를 생략하지 않는다. 출처 확인 시각에는 한국 시간이라는 표기를 붙인다.

## 독립 검토 수정과 Node 22 재검증

`docs/frontend-review.md`의 P2 두 건과 P3 두 건을 브라우저에서 재현했다. 실제 수집 자료에서 확인한 해설 준비 상태도 함께 검증했다.

| 항목 | 수정 내용 |
| --- | --- |
| 첫 수집 대기 | 성공 기록 없는 출처는 대기나 실패로 표시한다. 성공한 확인 시각이 API 기준인 26시간을 넘은 경우에만 오래된 자료라고 안내한다. |
| 최신 상태 확인 실패 | 성공 시각이 최근인데 API가 저장된 스냅샷을 최신으로 확인하지 못한 경우, 경과 시간 대신 최신 수집 상태를 확인하지 못했다고 설명한다. |
| 홈 이동 | 홈 이동과 목록 복귀의 의도를 구분한다. 홈은 상단 제목으로 이동하고 뒤로 가기는 목록 위치와 초점을 복원한다. |
| 반복 저장 알림 | 알림마다 발생 번호를 부여한다. 문구가 같아도 새 저장 동작은 별도의 상태 알림으로 표시한다. |
| 날짜 범위 연도 | 날짜 버튼과 활성 필터에 연도를 포함한다. 한쪽만 지정한 범위에도 연도를 표시하며 모바일에서는 두 줄로 줄바꿈한다. |
| 해설 준비 상태 | 해설 안내는 현재 글의 `explanationStatus`로 판단한다. 출처가 정상이고 해설만 준비 중이면 출처 실패로 표시하지 않는다. 모든 글의 해설이 준비되면 이전 실행의 `partial` 기록이 남아 있어도 해당 안내를 없앤다. |
| 한국어 문구 | 우측 문구를 “공식 릴리스를 모아 새 기능과 적용 조건을 설명합니다.”로, 하단 문구를 “공식 릴리스의 새 기능과 적용 조건”으로 바꿨다. |

수집 상태 판단은 `src/client/lib.ts`의 `getCollectionState`에서 공통으로 처리한다. 상단 상태, 목록 아래 확인 상태와 안내 영역이 같은 기준을 사용한다.

추가한 `tests/browser/review.spec.ts`는 다음 12개 동작을 확인한다.

1. 첫 수집을 기다리는 응답에서 오래된 자료 안내를 생략한다.
2. 오늘 확인한 출처와 처음 기다리는 출처가 함께 있어도 성공 기록을 오래된 자료로 설명하지 않는다.
3. 첫 수집이 모두 실패했을 때 이전 글이 있다고 안내하지 않는다.
4. 최근 성공 기록이 있는 저장된 스냅샷에는 최신 상태를 확인하지 못했다는 안내를 쓴다.
5. 목록 아래에서 글을 연 뒤 홈을 누르면 스크롤과 초점이 상단 제목으로 이동한다.
6. 첫 저장 알림이 사라진 후 다른 글을 저장하면 같은 문구의 알림이 다시 나온다.
7. 여러 해에 걸친 범위를 적용하면 양쪽 연도를 표시하며 390px 화면에 가로 넘침이 없다.
8. 시작일만 지정해도 해당 연도를 표시한다.
9. 종료일만 지정해도 해당 연도를 표시한다.
10. 출처가 모두 정상인 부분 실행에서는 준비 중인 해설을 안내한다.
11. 해설 보완 후 모든 글이 준비되면 이전 부분 실행 이력만으로 경고하지 않는다.
12. 실행 이력이 성공이어도 현재 준비 중인 해설이 있으면 안내한다.

처음 추가한 10개 검증에서 각각 문제를 재현했다. 날짜 범위, 홈 탐색, 저장 알림과 수집 상태를 나누어 수정한 뒤 관련 검증을 통과했다. 현재 해설 상태와 과거 실행 이력의 관계를 확인하는 두 검증도 추가했다.

최종 브라우저 명령:

```bash
npm exec --offline --package=node@22 --cache /tmp/code-pulse-npm-cache -- npm run test:browser
```

결과는 Chromium 31개 통과, 12.7초, 종료 코드 0이다. 같은 Node 22 실행 환경에서 프런트엔드 파일, 공유 타입, 브라우저 테스트와 Playwright 설정을 대상으로 `tsc --noEmit`을 실행했다. 프로젝트와 같은 엄격한 옵션을 적용했고 종료 코드 0을 확인했다.

추가 화면 `/tmp/code-pulse-mobile-year-range.png`를 직접 열어 여러 해에 걸친 날짜 범위의 줄바꿈을 확인했다. 기존 데스크톱과 모바일 화면 캡처도 전체 브라우저 검증에서 다시 생성했다.

이 단계에서는 부모 작업의 패키지 업그레이드가 진행 중이어서 전체 빌드를 다시 실행하지 않았다. 수정과 검증 범위는 처음 지정된 프런트엔드 파일, 브라우저 테스트와 이 보고서다.

## 공식 제품 로고 적용

공식 페이지의 HTML에서 실제로 참조하는 로고 이미지를 찾아 로컬에 저장했다. 원본 URL, 발견한 페이지, 변환 여부와 SHA-256은 [공식 로고 출처](../public/brand/SOURCES.md)에 기록했다.

| 제품 | 표시 파일 | 발견 위치 |
| --- | --- | --- |
| Claude Code | `/brand/claude-code.png` | 사용자가 지정한 공식 문서 두 페이지의 192px 아이콘 링크 |
| Codex | `/brand/codex.png` | OpenAI의 Codex Windows 앱 문서에 포함된 앱 로고 이미지 |
| Kiro | `/brand/kiro.svg` | Kiro 공식 사이트의 SVG 아이콘 링크 |

Claude Code의 라이트 모드와 다크 모드 원본은 바이트가 같아 한 파일을 사용한다. Codex는 공식 WebP 원본을 보관하고 같은 크기의 PNG로 변환했다. 두 파일을 RGBA로 읽은 픽셀 바이트가 모두 같은지 확인했다. Kiro는 공식 SVG를 그대로 저장했다.

`ProductMark`가 제품 필터, 활동표, 글 목록과 상세, 출처 요약과 dialog에서 같은 로컬 이미지를 표시한다. 고정된 표식 영역 안에서 원본 비율과 색상을 유지한다. 제품 이름, 빈 이미지 `alt`와 장식 표식의 `aria-hidden="true"`를 사용한다. Code Pulse의 자체 로고와 조작 아이콘은 유지했다.

프런트엔드 링크 검사는 `https://code.claude.com/docs/ko/whats-new`와 `https://code.claude.com/docs/en/changelog`를 허용한다. 상세의 공식 원문과 추가 출처 링크가 두 주소를 그대로 제공하는지 브라우저에서 확인했다.

Node 22.23.3에서 `npm run test:browser`를 실행한 결과 Chromium 33개가 13.5초에 통과했다. `tests/browser/branding.spec.ts`에서는 공식 로고가 실제로 로드되는지, 이미지가 같은 출처에서 제공되는지, 두 테마에서 표시되는지와 Claude Code 공식 링크를 검증한다. 프런트엔드와 브라우저 테스트를 대상으로 엄격한 TypeScript 검사도 통과했다.

## 방문 집계와 서비스 변경 기록

Robot Atlas의 `presence.ts`와 하단 화면 구성을 읽기 전용 참고 자료로 확인했다. Code Pulse의 API 계약에 맞춰 `src/client/presence.ts`와 `src/client/footer.tsx`를 구현했다.

방문 집계는 `/api/presence`를 GET으로 읽어 쿠키를 준비한 다음, 빈 JSON 본문과 `x-code-pulse-client: 1`을 담은 POST로 접속을 갱신한다. 두 요청 모두 `credentials: same-origin`을 사용한다. 숫자는 검증된 서버 응답에서만 가져오며 브라우저에 방문 수나 방문자 ID를 따로 저장하지 않는다.

화면이 보이고 온라인인 동안 30초마다 갱신한다. 숨긴 탭과 `pagehide`, 오프라인 상태에서는 예약과 진행 중인 요청을 멈춘다. 다시 표시되면 갱신을 재개하며, 동시에 여러 요청을 보내지 않는다. 요청은 8초로 제한하고 POST가 401 또는 403이면 쿠키 준비를 한 번 반복한다.

하단에 `접속 n`과 `누적 방문 n`을 CSS 간격으로 나누어 표시한다. 첫 응답 전에는 확인 중, 확인할 수 없고 이전 값도 없으면 확인 불가로 표시한다. 이전 실제 값이 있으면 지우거나 임의 숫자로 바꾸지 않고 마지막 확인값임을 알린다. 90초보다 오래되거나 갱신에 실패한 응답도 같은 방식으로 구분한다.

집계 기준은 마우스, 터치와 키보드로 열 수 있는 tooltip에 설명한다. 90초 기준, 같은 브라우저의 새로고침과 여러 탭, 갱신 주기, 확인 시각과 집계 시작 시각을 안내한다. Escape와 초점 이동으로 닫을 수 있다.

버전 버튼은 Vite의 `__APP_VERSION__` 값을 표시하며 현재는 `v1.0.0`이다. `src/shared/app-release.json`에서 한국어 변경 내용을 읽어 `Code Pulse 변경 기록` 모달에 표시한다. 모달을 닫으면 버전 버튼으로 초점이 돌아간다. 서비스 버전과 변경 기록을 표시하기 위한 외부 Git 태그나 원격 릴리스 링크는 만들지 않았다.

추가한 `tests/browser/footer.spec.ts`는 다음 동작을 검증한다.

1. GET 뒤 POST를 보내고 준비한 쿠키, 지정 헤더와 빈 JSON을 사용한다.
2. 첫 응답을 기다릴 때 숫자를 만들어 넣지 않는다.
3. 집계 API에 실패해도 검색과 글 읽기를 사용할 수 있다.
4. 30초 갱신, 숨긴 탭의 중단과 표시 후 재개를 처리한다.
5. 오래된 응답의 실제 숫자와 마지막 확인 표식을 유지한다.
6. 갱신 실패 후에도 마지막으로 받은 숫자를 보존한다.
7. 잘못된 집계 응답은 숫자로 표시하지 않는다.
8. 세션이 만료되면 준비한 새 쿠키로 한 번 재시도한다.
9. 처음부터 숨겨진 페이지는 표시되기 전까지 방문 요청을 보내지 않는다.
10. 390px에서 tooltip과 한국어 변경 기록 모달을 키보드로 사용하고 초점을 복원한다.

기존 브라우저 fixture에도 방문 집계 API를 추가했다. 통합 브라우저 검증은 43개가 16.5초에 통과했고 프런트엔드 타입 검사와 `npm run release:check`도 성공했다. 릴리스 검사에서 버전 1.0.0과 CHANGELOG, README, 생성된 릴리스 문서의 일치를 확인했다.
