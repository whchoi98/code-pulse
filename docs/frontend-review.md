# Code Pulse 프런트엔드 독립 리뷰

검토일: 2026-10-07

규격 판정은 **수정 필요**다. 주요 화면과 탐색 기능은 구현되어 있지만, 첫 수집 대기와 오래된 자료를 구분하는 요구가 초기 API 응답에서 충족되지 않는다. 품질 판정도 **수정 필요**다. 홈 이동의 스크롤 처리에서 재현한 문제가 있다. P2 두 건과 P3 두 건을 아래에 기록했다.

## 확인한 문제

### [IMPORTANT] P2 첫 수집 대기에 오래된 자료 안내가 함께 나온다

**위치:** `src/client/components.tsx:71`  
**계약 근거:** `src/server/app.ts:72`  
**확신도:** 99/100

API는 마지막 성공 시각이 없는 출처도 `stale: true`로 반환한다. 최초 수집 전처럼 모든 출처가 `pending`이고 `latestRun`과 성공 기록이 없는 응답을 넣으면, 화면 상단에는 “첫 출처 확인 대기”가 나오면서 자료 상태에는 “마지막 확인 이후 시간이 지났습니다”가 함께 나온다. 아직 확인한 적이 없는 자료를 오래된 자료로 설명한다.

초기 수집 대기와 과거 자료의 유효 기간을 구분해야 한다. 성공 기록이 없는 출처는 대기 또는 실패 상태로 안내하고, 실제로 과거 확인 기록이 오래된 경우에만 해당 문구를 표시하는 방식이 적절하다. 최초 응답을 사용하는 회귀 검증이 필요하다.

### [IMPORTANT] P2 상세 화면의 홈 이동이 이전 목록 위치로 되돌아간다

**위치:** `src/client/App.tsx:41`  
**관련 위치:** `src/client/App.tsx:139`  
**확신도:** 100/100

상세 화면을 벗어날 때마다 같은 effect가 이전 목록의 스크롤과 초점을 복원한다. 홈 로고의 `window.scrollTo(0, 0)`도 그다음 프레임에 덮어쓴다.

목록 아래의 글을 연 뒤 홈 로고를 누르는 브라우저 점검에서 주소는 홈으로 바뀌었지만, 스크롤은 `893px`로 돌아갔고 초점도 `entry-link-claude-older`에 놓였다. 홈의 제목과 탐색 영역으로 이동하려는 동작과 맞지 않는다.

목록 복원은 뒤로 가기와 목록 복귀에 적용하고, 홈 이동은 상단 위치와 적절한 초점을 유지하도록 이동 의도를 구분해야 한다.

### [IMPORTANT] P3 같은 종류의 저장 알림이 다시 표시되지 않는다

**위치:** `src/client/App.tsx:63`  
**관련 위치:** `src/client/hooks.ts:75`  
**확신도:** 100/100

알림 effect는 `saved.notice` 문자열이 바뀔 때 실행된다. 첫 저장 알림이 4.5초 뒤 사라져도 이 문자열은 남는다. 다른 글을 이어서 저장하면 같은 문자열이 설정되므로 토스트와 상태 알림이 다시 나오지 않는다.

브라우저에서 첫 글을 저장하고 4.6초 뒤 두 번째 글을 저장했다. 두 글의 ID는 localStorage에 남았지만 두 번째 토스트는 빈 문자열과 숨김 상태였다. 저장 자체는 성공하며, 반복되는 저장 결과 안내가 빠지는 문제다.

알림에 발생 번호를 붙이거나 표시가 끝난 알림을 소비하는 방식으로, 문구가 같아도 각각의 저장 동작을 알릴 수 있어야 한다.

### [IMPORTANT] P3 여러 해에 걸친 날짜 범위가 짧은 기간처럼 보인다

**위치:** `src/client/App.tsx:132`  
**확신도:** 100/100

범위 표시가 두 날짜의 연도를 항상 제거한다. `2025-10-05`부터 `2026-10-06`까지 선택하면 날짜 버튼과 활성 필터 모두 `10.05 ~ 10.06`으로 표시된다. 실제 필터는 1년이 넘는 범위에 적용되지만 화면에서는 이틀처럼 보인다.

양 끝의 연도가 다르면 연도를 포함해야 한다. 한쪽 날짜만 선택한 경우에도 현재 연도와 다른 날짜는 연도를 보여주는 편이 명확하다.

## 충족한 요구

- 목록 정렬, 날짜 필터와 활동표가 `publishedDate`를 사용한다. 수집 시각으로 발표일을 바꾸지 않는다.
- 날짜 정밀도가 `day`인 상세에는 발표 시각을 추가하지 않는다. 시각이 있는 자료에는 한국 시간으로 환산한 전체 날짜와 시각이 따로 나온다.
- 제품, 검색어, 종류, 날짜와 저장 필터를 URL에서 복원한다. 저장 목록은 localStorage를 사용하며 저장 실패 시 현재 창의 상태를 유지한다.
- 상세에는 AI 해설 표식, 의미, 확인할 사항, 짧은 원문 근거와 공식 링크가 있다. `originalText`를 화면에 렌더링하지 않는다. 실제 상세 API도 원문 본문과 해시를 빈 문자열로 제거한다.
- API 실패, 없는 글, 해설 준비 중과 일부 출처 실패에 대한 화면이 있다.
- dialog의 초점 처리와 Escape 닫기, 본문 바로가기, 라이트와 다크 테마, reduced-motion 처리가 구현되어 있다.
- 화면 문구에서 사용자가 금지한 두 구분 기호를 새로 사용한 부분은 발견하지 못했다.

## 검증 범위와 한계

지정한 작업 지시, 설계와 구현 보고서를 읽고 `index.html`, `src/client/**`, `public/theme.js`, `public/fonts/fonts.css`, `tests/browser/**`를 검토했다. 초기 수집 상태와 원문 비공개 계약을 확인할 때만 공유 타입과 API의 관련 코드를 읽었다.

구현 보고서의 빌드, 타입 검사와 Chromium 19개 테스트 통과 기록을 확인했다. 이 리뷰에서 해당 모음을 다시 실행하지 않았다. 기존 fixture를 사용하는 별도 Chromium 점검으로 다음 결과를 얻었다.

| 점검 | 결과 |
| --- | --- |
| 320, 360, 390, 641, 768px의 날짜 dialog와 출처 dialog | 내부 가로 넘침 없음 |
| 같은 너비의 날짜 범위 적용 목록과 상세 | 문서 가로 넘침 없음, JavaScript 오류 없음 |
| 첫 수집 대기 응답 | P2 상태 안내 문제 재현 |
| 상세 화면에서 홈 로고 이동 | P2 스크롤과 초점 문제 재현 |
| 같은 문구의 저장 알림 반복 | P3 알림 문제 재현 |
| 여러 해에 걸친 날짜 범위 | P3 연도 누락 문제 재현 |

실제 외부 자료의 수집 성공, 공개 배포 주소와 AWS 구성은 검토 범위 밖이다. 앱 파일, 테스트 파일과 Git 상태는 변경하지 않았다. 이 보고서만 작성했다.

재검토일: 2026-10-07

앱과 테스트 파일은 수정하지 않았다. 이 절만 보고서에 추가했다. 실제 수집 자료와 공개 배포 주소의 최종 확인은 부모 작업에서 진행한다.
