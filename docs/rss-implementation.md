# RSS 구독

Code Pulse의 RSS는 저장된 한국어 해설을 읽어 제공합니다. 요청을 처리할 때 공식 출처를 다시 수집하거나 모델을 호출하지 않습니다.

| 주소 | 수록 범위 |
| --- | --- |
| `/feed.xml` | 세 제품 전체 |
| `/feed.xml?product=claude-code` | Claude Code |
| `/feed.xml?product=codex` | Codex |
| `/feed.xml?product=kiro` | Kiro |

각 피드는 해설이 준비된 글을 원문 발표 시각의 내림차순으로 최대 50개 제공합니다. 제품을 먼저 고른 뒤 개수를 제한합니다. 발표 시각이 같으면 ID의 오름차순으로 정렬하므로 저장 순서나 서버 언어 설정이 달라도 순서가 유지됩니다. 준비 중인 글, 해설이 없는 글, 해석할 수 없는 발표 시각과 미래 발표는 제외합니다. 요청 시각과 발표 시각이 같은 글은 포함합니다.

`product`를 생략하면 전체 피드입니다. 빈 값, `all`, 알 수 없는 제품, 반복된 `product`와 지원하지 않는 쿼리 키는 `400`으로 응답합니다. 오류 응답은 캐시하지 않습니다.

RSS의 제목과 본문은 공개 해설의 제목, 요약과 변경 의미를 사용합니다. 본문에는 `AI 해설` 표시, 원문 발표일, Code Pulse 상세 화면과 공식 원문으로 가는 링크가 있습니다. 공식 원문 주소는 기존 수집기의 허용된 HTTPS 출처 목록으로 검사합니다. 허용되지 않는 주소는 링크로 내보내지 않습니다. 전체 원문, 내용 해시, 모델 식별자와 방문 데이터는 피드에 포함하지 않습니다.

항목의 `guid`는 `isPermaLink="true"`인 Code Pulse 상세 주소입니다. 한국어를 편집하거나 출처를 다시 확인해도 ID가 같으면 이 값은 바뀌지 않습니다. `pubDate`는 저장된 `publishedAt`을 RSS 날짜 형식으로 변환합니다. 수집 시각이나 편집 시각으로 바꾸지 않습니다. 날짜만 알려진 기록도 저장된 값을 전송하되 본문에 `발표 시각 미제공`을 표시합니다. 초기 스냅샷이 비어 있으면 항목과 날짜를 만들지 않은 정상 RSS 채널을 반환합니다.

기준 주소는 `ServerOptions.publicBaseUrl`, 환경변수 `PUBLIC_BASE_URL` 순서로 선택합니다. 운영에서는 HTTPS 루트 주소가 필요합니다. 사용자 정보, 경로, 쿼리와 프래그먼트가 들어간 값은 서버 시작 시 거부하며 오류에 입력값을 출력하지 않습니다. 운영 외 환경에서만 HTTP를 허용하고, 설정이 없으면 `http://localhost:8080`을 사용합니다. 요청의 Host나 전달 헤더로 구독 주소와 글 주소를 만들지 않습니다.

XML은 RSS 2.0이며 응답 형식은 `application/rss+xml; charset=utf-8`입니다. 채널에는 한국어 언어 코드와 Atom의 자기 참조 링크를 넣습니다. 본문 텍스트와 링크 속성을 HTML로 이스케이프한 다음, 완성된 HTML을 다시 XML 텍스트로 인코딩합니다. XML 1.0에서 허용하지 않는 제어 문자와 짝이 없는 서로게이트는 대체 문자로 바꿉니다. `index.html`에는 전체 피드를 찾을 수 있는 RSS 자동 검색 링크가 있습니다.

RSS는 `/api/feed`와 같은 스냅샷 캐시를 사용합니다. 정상 응답의 캐시는 `public, max-age=30, s-maxage=60`입니다. 저장소를 처음부터 읽지 못하면 `503`과 `no-store`를 반환합니다. 이전 스냅샷이 있으면 그 자료를 `200`으로 제공하되 `no-store`를 설정합니다. 저장소가 복구되면 다음 읽기부터 정상 캐시 정책을 사용합니다. 기존 CloudFront 기본 동작은 쿼리 문자열을 캐시 키에 포함하므로 제품별 피드에 별도 인프라가 필요하지 않습니다.

2026년 10월 8일에 RSS Advisory Board의 공식 RSS 2.0 규격을 확인했습니다. 필수 채널 요소, XML 1.0 호환성, 날짜 형식, 항목 식별자와 엔티티로 인코딩한 HTML 설명 규칙을 기준으로 구현했습니다.

규격 주소: `https://www.rssboard.org/rss-specification`

Node.js 22.23.3에서 새 RSS 테스트 41개가 구현 전 실패한 것을 확인했습니다. 구현 후 다음 명령으로 RSS와 기존 서버, 방문 집계 HTTP 테스트 66개가 통과했습니다.

```bash
npm test -- tests/rss.test.ts tests/server.test.ts tests/presence-http.test.ts
```

테스트는 메모리 스냅샷과 고정 시각을 사용합니다. XML을 파싱하고, 설명의 HTML을 다시 파싱해 링크와 텍스트가 안전하게 남는지 검사합니다. 제품 선택, 50개 제한, 미래 기록 제외, 발표일과 GUID 보존, 저장소 장애와 복구, 잘못된 설정, Host 헤더 조작과 비공개 필드 제외를 확인합니다. AWS, 모델과 실제 수집 API는 호출하지 않습니다. 배포 후 공개 HTTPS 응답과 구독 화면 확인은 별도 검증 기록으로 남깁니다.
