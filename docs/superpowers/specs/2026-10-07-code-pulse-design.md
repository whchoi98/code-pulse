# Code Pulse 설계

## 목적

Claude Code, Codex, Kiro의 공식 변경 기록을 매일 확인하고, 새 기능과 실무에서 달라지는 점을 한국어로 소개한다. 기존 게임 사이트의 VPC를 사용하며 CloudFront, Prefix List 보안 그룹, ALB, ECS Fargate 순서로 요청을 처리한다.

## 독자와 화면

코딩 도구를 사용하는 개발자가 최근 변경을 읽고 적용 여부를 판단하는 공개 사이트다. 로그인은 필요 없다. 제품 필터, 검색, 날짜 선택, 변경 종류 필터, 저장한 글, 원문 링크를 제공한다. 글을 열면 바뀐 내용, 의미, 확인할 사항과 근거를 보여준다. 브라우저에 저장한 글은 같은 기기에서 다시 볼 수 있다.

밝은 회청색 바탕, 짙은 남색 글자, 청록색 강조를 사용한다. 제품 표식은 Claude Code, Codex, Kiro 공식 로고 파일을 사용하며 이름을 함께 표시한다. 글을 읽는 영역은 차분하게 유지하고 최근 7일의 제품별 변경을 보여주는 작은 활동표로 날짜를 탐색한다. 모바일에서도 검색과 필터를 사용할 수 있어야 한다.

색상 토큰: paper #f4f7fb, surface #ffffff, ink #17283f, muted #617086, accent #087f8c, line #dce4ed. 제목은 Space Grotesk와 한국어 고딕 대체 글꼴, 본문은 Noto Sans KR, 버전과 날짜는 IBM Plex Mono를 사용한다. 글꼴은 가능한 한 자체 호스팅한다.

## 문체

사용자가 요청한 human-ton 기준을 적용한다. 과장, 번역투, 불필요한 수식, 기계적인 접속사를 줄인다. 한국어 서비스 문구와 생성 해설에서 엠대시와 가운뎃점을 사용하지 않는다. 직접 인용과 코드, 공식 원문은 내용 보존을 우선한다. 새 사실을 만들거나 조건과 적용 범위를 바꾸지 않는다. 기능 이름과 구체적인 변화가 먼저 나오게 쓴다.

## 공식 자료

1. Claude Code: anthropics/claude-code 공식 GitHub Releases.
2. Codex CLI: openai/codex 공식 GitHub Releases. 시험판은 기본 피드에서 제외한다.
3. Codex 제품: 공식 Codex changelog RSS. 현재 learn.chatgpt.com으로 이동하며 ChatGPT 글도 포함하므로 Codex 관련 항목만 사용한다.
4. Kiro: kiro.dev/changelog의 CLI, IDE, Web 변경 기록.
5. Claude Code 영문 공식 변경 기록: `https://code.claude.com/docs/en/changelog`. 날짜가 명시된 안정판을 수집하며 같은 버전의 GitHub 기록과 합친다.
6. Claude Code 한국어 새 소식: `https://code.claude.com/docs/ko/whats-new`. 주간 버전 범위에 맞는 릴리스의 배경 자료로 읽는다. 주간 범위를 개별 발표일이나 그 버전의 전체 변경 목록으로 취급하지 않는다.

변경 기록에 연결된 공식 블로그는 필요할 때만 보충 자료로 읽는다. 허용된 공식 도메인과 경로를 확인하고 리디렉션도 검증한다. 수집 문서는 명령이 아닌 자료로 취급한다.

실제 발표일과 수집 시각은 별도로 저장한다. 날짜만 제공되는 자료에 임의 시각을 붙여 날짜를 이동시키지 않는다. 미래에 발표된 것처럼 보이는 항목은 공개하지 않는다. URL과 내용 해시로 중복을 막고 원문 수정도 추적한다.

수집 범위는 2026년 1월 1일부터 현재까지다. 공식 이전 페이지를 따라 과거 자료를 읽고 시작일의 기록도 포함한다. 오래된 글에 붙은 패치는 별도 버전과 발표일이 명시된 경우 그 날짜로 보완하며 타임라인의 같은 패치와 중복되지 않게 한다.

## 해설

Bedrock의 `global.anthropic.claude-haiku-5-5` 추론 프로필로 한국어 초안과 윤문을 수행한다. JSON 구조를 검증하고 각 주요 변경의 근거가 원문에 있는지 확인한다. 생성 해설과 공식 발표를 구별한다. 원문에 없는 가격, 명령어, 성능 수치를 만들지 않는다.

요약에 실패한 항목은 원문을 보존하고 해설 준비 상태로 표시한다. 다음 실행에서 재시도한다. 일부 출처가 실패해도 다른 제품의 수집과 기존 글 조회는 계속된다. 모든 출처가 실패하면 실행 실패로 기록한다.

모델을 변경한 뒤에는 `--refresh-model`로 기존 글을 갱신할 수 있다. 검증에 성공한 해설부터 교체하며 실패한 글은 기존 해설을 유지한다. 원문과 보충 배경 본문은 공개 API에 제공하지 않는다.

과거 해설은 해당 발표 시점의 변경으로 설명한다. 이미 지난 종료 일정을 미래의 일처럼 쓰거나 당시의 기능을 지금도 제공한다고 단정하지 않는다.

## 저장과 실행

TypeScript를 사용한다. React와 Vite로 화면을 만들고 Fastify가 정적 파일과 읽기 API를 제공한다. 웹 서버는 수집이나 모델 호출 권한을 갖지 않는다.

S3의 비공개 버킷에 원문과 버전이 있는 JSON 스냅샷을 저장한다. 스냅샷은 ETag 조건부 쓰기로 갱신해 동시 실행의 결과가 사라지지 않도록 한다. 수집 실패 시 기존 글을 지우지 않는다. 로컬에서는 파일 저장소를 사용한다.

EventBridge Scheduler가 매일 09:00 Asia/Seoul에 별도 Fargate 수집 태스크를 실행한다. 최근 자료를 처음 한 번 수집하고 이후 변경분만 해설한다. 재실행은 안전해야 한다. 실행 기록, 마지막 성공 시각, 출처별 오류를 남긴다. 화면은 오래된 자료와 정상 확인 후 새 소식이 없는 상태를 구분한다.

## AWS

확인된 계정은 061525506239, 리전은 ap-northeast-2다. VPC는 vpc-0dfa5610180dfa628이며 기존 NAT와 S3 엔드포인트를 재사용한다.

ALB는 기존 퍼블릭 서브넷 두 곳에 둔다. 80번 포트의 인바운드는 CloudFront origin-facing Prefix List pl-22a6434b만 허용한다. CloudFront가 전용 헤더를 추가하고 ALB는 올바른 헤더가 있는 요청만 전달한다. 기본 응답은 403이다. 사용자 연결은 HTTPS이며 기존 게임 사이트처럼 CloudFront에서 ALB까지는 HTTP를 사용한다.

웹 서버와 수집 태스크는 기존 프라이빗 서브넷에서 실행하며 공인 IP를 할당하지 않는다. 웹 서버는 256 CPU, 512 MiB, ARM64 한 대로 시작한다. 수집 태스크는 512 CPU, 1024 MiB, ARM64를 사용한다. 서비스는 최대 두 대까지 확장할 수 있다. 별도 VPC나 NAT는 만들지 않는다.

CloudWatch 로그, 수집 실패 알람, ALB 오류 알람과 Scheduler DLQ를 구성한다. 원문 버킷은 암호화, 공개 차단, 버전 관리를 사용하며 스택 삭제 시 보존한다. 기본 접속 주소는 CloudFront 도메인이다. 사용자가 별도 도메인을 선택하면 기존 인증서와 DNS 상태를 확인해 적용한다.

## 검증

공식 원문으로 파서, 날짜, 시험판 제외, 중복 처리와 오류 격리를 검증한다. 생성 해설의 근거와 문체 규칙을 검증한다. 브라우저에서 검색, 필터, 저장, 상세 보기, 키보드 탐색, 모바일 화면을 확인한다. CDK 템플릿과 실제 AWS 리소스에서 VPC 재사용, Prefix List 제한, 프라이빗 태스크와 일일 일정을 확인한다. 공개 HTTPS 접속과 수집 태스크의 실제 성공을 확인한 뒤 완료한다.
